# 性能优化与并发控制规范

> **当前基线（2026-08-18）**：本文档说明系统的多级缓存架构、并发抓取控制策略、长任务串行化与响应性能调优方案。

---

## 性能架构概览

系统针对高频读、大批量外部同步与复杂指标聚合，设计了三层性能保障机制：

```
┌────────────────────────────────────────────────────────┐
│ 第一层: 内存业务缓存 (Memory Cache, TTL 5 min)          │
│   ├── 套餐推荐列表、分类列表、实时大盘                  │
│   └── 单飞去重 (In-flight Dedup): 共享同一外部请求      │
├────────────────────────────────────────────────────────┤
│ 第二层: 预聚合数据库快照 (Pre-aggregated Cache)         │
│   ├── DailyMetrics: 历史 GMV / 订单 / 商家日聚合        │
│   └── PackageSalesDaily: 套餐日销售金额与数量快照       │
├────────────────────────────────────────────────────────┤
│ 第三层: 受控串行全量同步 (Serial Background Tasks)      │
│   ├── 会员目录 (16万+)、门店目录 (1900+)、提货分 (1.5万+)│
│   └── 串行分页抓取 + 新代 staging 写入 + 单事务指针切换 │
└────────────────────────────────────────────────────────┘
```

---

## 核心优化策略

### 1. 单飞并发去重 (In-Flight Single-Flight)
- **场景**：当 5 分钟缓存失效时，多个并发前端请求同时到达。
- **方案**：`DataSourceService` 通过 `inFlight` Promise 锁，使同一时刻仅向外部 JeeSite 发起一次实际请求，其余请求等待该 Promise 完成并共享结果，彻底避免缓存击穿。

### 2. 外部抓取并发控制
- **配置**：`EXTERNAL_FETCH_CONCURRENCY=2`（代码设有硬上限 `4`，超时限制 `EXTERNAL_FETCH_TIMEOUT_MS=8000`）。
- **目的**：限制并发分页抓取数量，保护外部 JeeSite 服务免于高并发过载，同时保证首屏快速加载。

### 3. 大数据量快照的短事务原子切换
- **问题**：十万级全量数据写入若使用单一数据库长事务，会触发 SQLite 锁争用或 Prisma 事务超时（5秒）。
- **方案**：采用「分批串行写入新代暂存区（staging）+ 极短事务推进活动指针」机制，即使单次外部同步耗时数分钟，也不阻塞正常的读请求。

## 性能测试与调优

### 运行性能测试

```bash
npm run test:perf
```

### 生产推荐参数

```env
# 缓存有效期（5分钟）
CONTENT_CACHE_TTL_MS=300000

# 单次请求超时时间（8秒）
EXTERNAL_FETCH_TIMEOUT_MS=8000

# 分页抓取并发数（默认 2，最大 4）
EXTERNAL_FETCH_CONCURRENCY=2
```
