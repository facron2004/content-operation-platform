总览

这是一个设计良好的全栈项目，采用 NestJS（后端）+ Vue 3（前端）+ Prisma（ORM）+ SQLite（数据库） 技术栈，通过 npm workspaces monorepo 管理三个子包。整体代码质量较高，领域层采用纯函数设计使其可测试性极佳，缓存策略和错误处理也比较完善。

主要短板集中在 安全层面（缺少认证/授权、速率限制）和 前端工程化(prop drilling 严重、缺少全局错误边界）。下面对比列出亮点与问题：

设计模式评价

  • ✅门面模式：ContentService 作为聚合入口，将文案、预警、仪表盘委托给子服务，职责清晰。
  • ✅纯函数领域层：domain/ 目录下所有模块均无副作用，可独立测试，评分/标签/预警规则透明。
  • ✅适配器模式：jeesite-bargain-adapter.ts 将外部 API 数据适配为内部类型，兼容多种字段名变体。
  • ✅多层缓存：内存 TTL + inflight 去重 + 最小请求间隔 + 写后失效。
  • ⚠️缺少横切关注点：无全局 ExceptionFilter、无 AuthGuard、无 ThrottlerGuard、无 LoggingInterceptor。

P0 — 缺少认证和授权机制
当前所有 API 端点完全对外开放。建议添加 AuthGuard（基于 JWT 或 Session），结合角色体系（5 种角色）实现真正的权限控制，而不只是前端 UI 过滤。
P1 — 缺少全局异常过滤器
错误响应格式依赖 NestJS 默认行为。添加 ExceptionFilter 可统一 JSON 错误格式，方便前端消费。
P1 — health 端点信息泄露
/api/content/health 返回 process.uptime()、process.memoryUsage() 等敏感信息，在公网可访问时可能被利用做 DoS 分析。

需要改进

P2 — detail-cache.ts 无 LRU 上限
使用 Map 存储，仅 TTL 过期，无最大容量限制。长时间运行可能内存持续增长。建议添加 LRU 淘汰或设置 maxSize。
P2 — role 参数校验过宽
dashboard.controller.ts 中 @IsOptional() @IsString() 应改为 @IsOptional() @IsIn([...UserRole 枚举])。
P3 — daily-inventory-crawler 使用 $executeRawUnsafe
拼接 SQL 创建表时使用了模板字符串，但通过参数绑定传值，SQL 注入风险可控。建议迁移到 Prisma Migrate。

关键问题

P1 — GenerateView / AiConfigPanel prop drilling 严重
GenerateView 向 AiConfigPanel 传递 15+ 个 :prop 和 15+ 个 @update:xxx 事件，可读性和维护性极差。建议合并为 v-model:config 对象，或将状态提取到独立 composable。
P1 — 前端缺少全局错误边界
main.ts 中未配置 app.config.errorHandler，组件渲染错误会静默失败。同时缺少 window.addEventListener('unhandledrejection')。建议添加全局错误处理插件。
P1 — useDashboard 类型断言绕过类型检查
使用 as unknown as OperationConsoleData 强转类型，如果后端字段变更不会在编译期报错。
P2 — 前端内存缓存无 LRU 上限
cache.service.ts 使用 Map 无容量限制，cache key 用 JSON.stringify(params) 对对象键顺序敏感。
P2 — api.clearCache() 粒度过粗
写操作后全量清空缓存，可能误伤正在读取的无关请求。
P2 — ShellLayout 重复注册路由守卫
router.beforeEach/afterEach 在 ShellLayout.vue 中重复注册，与 router.ts 中的守卫冲突。
P2 — useAlerts 缺少请求竞态保护
快速切换筛选条件时，旧请求的响应可能覆盖新请求的结果。RecommendationsView 有 loadRequestId 保护，但 useAlerts 没有。
P3 — api 命名空间聚合对象为死代码
api.ts 第 44-53 行的 export const api = { getRecommendations, ... } 聚合导出未在任何文件中被使用，所有调用都是解构导入。
P3 — copyText 缺少 clipboard API fallback
某些环境下 navigator.clipboard 不可用，应 fallback 到 document.execCommand('copy')。
P3 — ShellLayout cookiePoller 清理是死代码
ShellLayout 是持久布局，不会触发 onUnmounted，但 onUnmounted 中写了清理逻辑。

审查意见

  • ✅外键级联删除：所有关联表使用 onDelete: Cascade，删除套餐时子数据自动清理，一致性好。
  • ✅索引设计：常用查询字段（areaId、merchantId、saleStatus、auditStatus、createdAt）均有索引，联合索引 (areaId, saleStatus) 覆盖区域+状态查询。
  • ⚠️SQLite 限制：SQLite 并发写入性能有限，作为本地工具足够，但不适合多用户高并发场景。
  • ⚠️无迁移版本管理：使用 prisma/create-schema.ts 手动执行 DDL，没有利用 Prisma Migrate 的版本历史。

总结

整体评分：B+ → A-（解决 P0/P1 问题后可提升至 A）


这是一个工程化水平较高的全栈项目。后端采用 NestJS 门面模式 + 纯函数领域层，架构优雅；前端使用 Vue 3 Composition API + TypeScript，类型安全。缓存策略、错误重试、自动登录等关键链路考虑周全。19 个测试文件覆盖了核心业务逻辑，domain 层的纯函数设计使得规则引擎高度可测。


主要不足集中在安全层面——在当前本地使用场景下（默认绑定 127.0.0.1，CORS 白名单限制 localhost），风险可控；但如果未来需要在局域网或公网部署，认证、授权、速率限制、安全头是必须补齐的基础设施。前端方面，GenerateView 的 prop drilling 问题需要优先重构。
